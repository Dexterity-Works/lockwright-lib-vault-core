## blind-relay 1.6.1

- `new Server({ createStream })` (`:12-22`). `createStream(opts)` must return a udx stream; the server calls it with `{ firewall }` (`:290-296`), connects it to the first incoming packet (`:345-349`), links the two ends with `stream.relayTo(remote.stream)` (`:312`), and listens for `error`/`close` (`:312`). - `Client.from(stream, { id })` memoised per stream (`:355-361`); `client.pair(isInitiator, token, stream)` returns a `Readable` that pushes the remote id (`:437-460`, `:504-534`); `unpair(token)` (`:462-470`). `token()` = 32 random bytes (`:536-539`).
- Hyperdht keeps the relay socket alive with `setKeepAlive(relayKeepAlive)` and times out pairing after 15 s (`connect.js:810-812`, `server.js:665-667`).

## Env vars and silent public fallbacks

- No `process.env` or `Bare.env` reads in any of these packages (grep over hyperdht, dht-rpc, hyperswarm, autopass, blind-pairing, blind-relay, autobase, corestore, secret-stream, udx-native, bogon, hyperdht-address, protomux). Only `hyperdht/bin.js` parses argv (`:19-23`).
- The only public-network constant is `BOOTSTRAP_NODES` (`hyperdht/lib/constants.js:17-21`). It is applied by `opts.bootstrap || BOOTSTRAP_NODES` (`hyperdht/index.js:28`), so `undefined`, `null`, `false`, `0`, `''` all select the public DHT. `[]` is truthy and yields an isolated node with no bootstrap (dht-rpc then maps it at `dht-rpc/index.js:36`; dht-rpc's own `=== false` branch is unreachable through hyperdht).
- Hyperswarm forwards `opts.bootstrap` unchanged (`hyperswarm/index.js:41`); Autopass and AutopassPairer default `bootstrap` to `null` (`autopass/index.js:26`, `:145`) and pass it through (`:40`, `:322`). Therefore `new Autopass(store)` or `Autopass.pair(store, invite)` without `bootstrap` (or without a prebuilt `swarm`) joins the public DHT.
- DNS: a bootstrap host that is not an IPv4 literal triggers `udx.lookup` (`dht-rpc/index.js:894-900`); the `ip@host:port` form first pings `ip` (`:884-892`).
- Relays: no built-in relay key list. `relayThrough` only dials what you pass (`hyperdht/lib/connect.js:809`). blind-peering only dials mirror keys stored in the view (`autopass/index.js:353-359`; `blind-peering/index.js:203`; `blind-peering/lib/client.js:98`). ## Recipes

(a) Local testnet with N bootstrap nodes and a Hyperswarm bound to it

```js
const createTestnet = require('hyperdht/testnet')
const Hyperswarm = require('hyperswarm')
const HyperDHT = require('hyperdht')

const testnet = await createTestnet(3, { host: '127.0.0.1' })  // ephemeral:false, firewalled:false, 127.0.0.1 (testnet.js:7-34)
const bootstrap = testnet.bootstrap                            // [{ host: '127.0.0.1', port }] (testnet.js:24)
const swarm = new Hyperswarm({ bootstrap })                    // or { dht: testnet.createNode() } (hyperswarm/index.js:38-46)
await swarm.dht.fullyBootstrapped()                            // dht-rpc/index.js:239-241
// later: await swarm.destroy(); await testnet.destroy()         // hyperswarm/index.js:588-604; testnet.js:66-74
```

Docker: `createTestnet(n, { host: '10.0.0.5' })` binds `0.0.0.0` and advertises `10.0.0.5` (`testnet.js:10`, `:24`); peers in other containers use that `bootstrap` array.

Size matters: two Hyperswarms on a testnet of one node never connect (measured: 15 s timeout with 1 node or a lone `new HyperDHT({ bootstrap: [], ephemeral: false, firewalled: false })`; 30 ms with 2 or 3 nodes on the loopback, same code). A single DHT node cannot broker the handshake between two peers. Across real links two nodes are still too few: a peer's bootstrap query (`dht-rpc/index.js:379-430`) finishes before the quick NAT probe it sent to the first node answers, so `_updateNetworkState` is never run (the fallback is the stable-ticks hook, ~20 min), the peer stays `firewalled=true` with `remoteAddress() === null`, and a stream punched to it times out (ETIMEDOUT after 13 s at 5, 10 and 20 ms link delay). With six nodes, or with the peers behind an easy NAT (same public host, LAN shortcut), data flows both ways in ~170 ms. Links with zero latency break the punch ordering even with the NAT state known. The lab therefore runs six nodes and a 5 ms base delay per link. Peers only need the first node's address; the rest are in its routing table.

(c) Classify a connection as direct / holepunched / relayed

```js
// relayAddrs: Set of 'host:port' per relay DHT server socket (relayDht.io.serverSocket.address(); if bound to 0.0.0.0 use the advertised IP, testnet.js:10,24)
function classify(conn, dht, relayAddrs) {
  const rs = conn.rawStream                                           // secret-stream/index.js:125
  if (!rs || !rs.connected) return 'pending'                          // udx stream.js:85-87
  if (relayAddrs.has(`${rs.remoteHost}:${rs.remotePort}`)) return 'relayed' // app stream rides the relay connection's socket+address (connect.js:825-829, server.js:685-689)
  if (dht._socketPool.lookup(rs.socket)) return 'holepunched'         // punch sockets come from the pool (holepuncher.js:14,145; socket-pool.js:28-30)
  if (rs.socket === dht.io.serverSocket || rs.socket === dht.io.clientSocket) return 'direct' // connect.js:230,258,544; server.js:404
  return 'unknown'
}
conn.rawStream.on('remote-changed', () => { /* relay -> direct upgrade (udx stream.js:476-484 via changeRemote connect.js:503 / server.js:337) */ })
```

Cross-check with counters sampled before/after: `dht.stats.punches.open` (direct), `.consistent`/`.random` (punch attempted), `dht.stats.relaying.successes` (relay paired) (`hyperdht/index.js:43-47`; increments `connect.js:231`, `holepuncher.js:189`, `:198`, `:204`, `server.js:405`, `:680`). Check `relayed` before the socket tests: a relayed stream's socket is whatever socket reached the relay, often `dht.socket`. Capture `rs.socket` and `remoteHost:remotePort` at `conn.on('open')` and again on `remote-changed`.
